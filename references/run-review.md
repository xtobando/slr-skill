# Formal review

1. Read the current protocol and workflow. Use PICOC where it helps define software engineering questions. Agree on the research questions, dates and sources, stage-specific inclusion/exclusion criteria, reviewer procedure, quality instrument and extraction variables. Initialize with `{SLR} --project PATH init`. Ask the reviewer to run `{SLR} --project PATH approve-protocol --reviewer ID` independently. A protocol/workflow amendment creates a new revision; retain the old decisions and identify affected items before rerunning a stage.
2. Read `status`, `workflow`, and `pending-review` before adding work. Use `records` for retained record IDs and `packet STAGE ENTITY_ID --output FILE` for the appropriate evidence packet. Use a small pilot first. Base batch size on reviewer capacity and ambiguous cases. Compare proposals with human pilot outcomes via `pilot-evaluation`.
3. For title/abstract or full-text screening, cite the applicable criterion, exact quote and source. Record uncertain cases explicitly; unsupported inferences, absent text, and PDF availability belong in notes or pending work. For quality and extraction, follow the configured scales and variables, supply a source anchor for each evidenced value, and preserve missingness rather than inventing values.
4. Draft to the current schema from `schema --output FILE` (starter example in [draft.schema.json](../templates/draft.schema.json)). Copy revision, stage, target, and evidence identifiers from the packet. Set provenance.wrapper explicitly to the actual runtime, such as claude-code or opencode, rather than relying on the legacy default. Keep provider/model/session provenance null when unknown. Run `submit DRAFT` and fix any validation failures from the source evidence. Give the resulting proposal ID and `{SLR} --project PATH review PROPOSAL_ID --reviewer ID` to the human. Use `review-sheet --reviewer ID` for a batch handoff, preserving blinding.
5. Progress after the workbench shows the required effective decision. Route disagreements to the protocol's independent review or adjudication. Have the reviewer use the dedicated retrieval and study-link commands when needed. Validate the attached documents before extracting. Distinguish a report from a study and avoid counting multiple reports of one study as independent evidence.

Expand `{SLR}` to the locked uv command in [setup](setup.md), or its documented Python fallback. Give the human fully expanded commands with absolute paths. Resolve all other relative paths from the review workspace.
